# النظام الموحد (Unified System)

برنامج سطح مكتب (Electron) بيجمّع التلات برامج في برنامج واحد:

التنقل: 11 قسم بترتيب تصميمك (راجع `docs/NAVIGATION.md`) — لوحة المتابعة العامة، مهامي، إدارة الموارد البشرية، إدارة العملاء والمشاريع،
الموردون، المخازن، حركة الموارد، الحسابات، التقارير، أرشيف عام الشركة، إعدادات عامة. بنفس شكل برنامج الموارد البشرية.

| البرنامج | الحالة |
|---|---|
| 👥 الموارد البشرية | **الأساس** — شغال زي الأصل |
| 🧾 الموردون والفواتير (الدفتر) | **مدموج بالكامل** (بياناته في `DATA.ledger`) |
| 🏗️ العملاء والمستخلصات | **دمج الدورة التجارية الأساسية 0.7.0** — العملاء شغّال؛ باقي الصفحات 0.7 |
| 📦 المخازن | قسم جديد — 0.9 |

**الإصدار الحالي: 0.7.0 — هيكل التنقل الجديد (11 قسم بتصميمك) + المرتجعات + نظرة عامة.** وحدة الموارد البشرية شغالة زي الأصل بالظبط،
ودفتر الموردين اتدمج فيه بالكامل: نفس النافذة والقائمة والإعدادات والمستخدمين والنسخ الاحتياطي، وبياناته في نفس ملف البيانات.
وحدة العملاء والمستخلصات لسه صفحة "قيد الدمج" (المرحلة 5).

## التشغيل
```
npm install
npm start          # تشغيل البرنامج
npm run check      # فحص سلامة الهيكل والأمان (من غير مكتبات)
npm test           # اختبارات الأمان والسيرفر (من غير مكتبات)
npm run dist       # بناء ملف التثبيت (Windows)
```

## البيانات — مهم
- البرنامج الموحّد له **مجلد بيانات مستقل** (اسمه من `productName`)، فتشغيله **لا يلمس** بيانات برنامج
  الموارد البشرية القديم ولا غيره.
- لو عايز تجرّب ببيانات HR الحقيقية: اقفل برنامج HR، وانسخ `data.json` (وفولدر `attachments`) من مجلد
  بياناته لمجلد بيانات البرنامج الموحّد — **نسخ، مش نقل**، وابدأ بنسخة احتياطية.
- لا تشغّل البرنامجين على نفس مجلد البيانات في نفس الوقت.
- **كلمات المرور:** أول تشغيل ببيانات HR قديمة بيحوّل كل كلمات المرور النصية لـ hash تلقائيًا. الحساب الافتراضي
  (`admin / admin123`) وأي حساب كلمته افتراضية معروفة هيتطلب منه تغيير كلمة المرور عند أول دخول. **خد نسخة احتياطية قبل أول تشغيل.**
- البرنامج الموحّد بيعتبر ملف بيانات من نسخة أحدث منه "للقراءة فقط" ومش بيكتب عليه.

## استيراد بيانات دفتر الموردين القديمة
الإعدادات (البيانات والتحديثات) ← تبويب **الموردون والفواتير** ← **📥 استيراد بيانات دفتر الموردين القديمة (data.json)**.
بياناتك بتتنقل لـ `DATA.ledger`، وإعدادات الملف القديم بتتدمج في إعدادات البرنامج، وسجل عملياته في سجل التدقيق (مع نسخة احتياطية قبل الاستبدال).
**المرفقات القديمة** محفوظة بمسارات كاملة على جهازك (مثل `C:\\...`) — سيب مجلد برنامج الدفتر القديم مكانه لحد ما نعمل أداة نقل المرفقات.

## قواعد للتطوير (لتجنب التصادم)
1. **مفاتيح الصفحات:** صفحات HR تحتفظ بمفاتيحها بدون بادئة؛ أي وحدة تانية تستخدم بادئتها
   (`ledger.invoices`, `clients.projects`) والرئيسية `<id>.home`.
2. **تغيير الاسم:** في 3 أماكن بالإضافة لـ brand.js — `npm run check` بيتأكد إنهم متطابقين.
3. **المحدّث:** بيقبل فقط حزم اسمها التقني `unified-system` (حماية من استبدال البرنامج بنسخة HR قديمة).
4. بعد أي تعديل في `index.html` أو سجل الوحدات: شغّل `npm run check`.
