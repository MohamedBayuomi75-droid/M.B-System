# خطة تطوير البرنامج الموحد — من «أجزاء مدموجة» إلى «كتلة واحدة»

نتيجة فحص الكود الحالي (1.2.0) ثم الخطة. كل رقم هنا من الكود نفسه.

## 1) نتيجة الفحص (الوضع الحالي)

### أ) مسار المشروع
- النسخة الأصلية (ملف العملاء) كانت بتعرض المسار كشريط أفقي: دوائر للمراحل + نقاط للخطوات على خط (`ppt-wrap / ppt-track / ppt-node`) مع تاريخ فوق كل خطوة وعدد المرفقات، وبالوناتة «رجوع» عند الضغط، ونسخة مصغّرة تحت كل صف مشروع، ونسخة تفاعلية داخل نافذة المشروع (128 قاعدة CSS).
- اللي نفذته أنا في المرحلة 3 و4 نقل **الوظائف** (بدء/إنجاز/تخطي/رفض/سجل/محرر المسار) لكن بتصميم مختلف (كروت `ppt2`). **ده مش نفس الشكل اللي طلبته** — هيتصلح في المرحلة ب.

### ب) الشكل العام
- صفحات الموارد البشرية بتستخدم «لوحات» (`board-card` + `entityDeptBoardsPageHtml`) في 11 ملف؛ العملاء والمشاريع والموردين والمخازن والحسابات صفحات جداول عادية بترويسة مختلفة.
- ملف CSS واحد 4224 سطر (+ `ledger.css` 3 أسطر، يعني تنسيق الموردين مدموج بالفعل) — فالتوحيد ممكن بدون إعادة كتابة.
- الإشعارات: `showToast` و`lgShowToast` (نسختين)، والتأكيد `confirmApp/confirmDelete` موحّد.

### ج) التنبيهات (5 أنظمة منفصلة)
| المصدر | المكان | الشكل |
|---|---|---|
| الموارد البشرية | `collectSystemAlerts` + `dashboardAlertsHtml` (كروت `alert-card`) | الشكل المعتمد |
| الموردين | `pages-dashboard.js` (فواتير متأخرة) | صندوق أحمر مستقل |
| المخازن | `pages-reports.js` (حد الطلب) | صندوق مستقل |
| العملاء | لوحة العملاء (أقسام المتابعة) + مهامي | أقسام مستقلة |
| الملاحظات | `notes-list / notes-ok / notes-detail-box` | في كروت الأفراد فقط |

### د) المصاريف والتكاليف الشاملة — **فجوة حقيقية**
`projectCostSummary` (اللي بيغذي ميزانية المشروع وتنبيهات التجاوز) بيجمع: يوميات العمال + يوميات المعدات + الوقود + صيانة المعدات + المصاريف + التكاليف **فقط**. مش بيدخل فيه:
1. **فواتير الموردين المربوطة بالمشروع** (`inv.project` موجود في الفواتير لكن مش داخل الحساب).
2. **صرف المخازن للمشروع** (`out` + `m.project` بتكلفة المتوسط).
3. **السلف** (المتغير `advances` ثابت = 0 ولا بيتحسب).
4. مرتبات الموظفين/المشرفين الموزّعة على المشروع.
وكمان: المشاريع في كل الأقسام مربوطة **بالاسم النصي** (`worker.project`, `expense.project`, `inv.project`…) مش بالـ id — يعني تغيير اسم مشروع بيكسر الربط.

## 2) الإضافات اللي أقترحها (قولي أيهم تعتمد)
1. **مركز تنبيهات واحد** بعدّاد في شريط التنقل + «تأجيل/تم» لكل تنبيه + ربط مباشر بالسجل.
2. **ربحية المشروع في كارت واحد:** إيرادات (مستخلصات/تحصيلات) − تكاليف شاملة (بند 1د) + المحتجز.
3. **خط زمني للمشروع** (Timeline): كل حدث على المشروع من أي قسم (خطوة مسار، حصر، عقد، مستخلص، دفعة مورد، صرف مخزن، يومية) في شاشة واحدة.
4. **بحث شامل** (عميل/مشروع/مورد/فاتورة/موظف) من شريط الأعلى.
5. **ربط المشاريع بالـ id** مع إبقاء الاسم للعرض (ترحيل آمن + تحديث تلقائي عند تغيير الاسم).
6. **اعتماد/موافقات** بسيطة على المصروفات الكبيرة والتكاليف (حد قابل للضبط).
7. **لقطة احتياطية تلقائية قبل كل ترحيل** (موجود جزئيًا — يتعمم).

## 3) الخطة (مرتبة بالأولوية والمخاطرة)

### المرحلة أ — نظام التصميم الموحد (أساس لكل اللي بعده)
- مكوّنات مشتركة واحدة: ترويسة صفحة، صف إحصاء، شريط فلاتر، **لوحات الأقسام** (`board-grid`)، جدول، بطاقة ملاحظة، تنبيه، Toast/تأكيد/نافذة. حذف `lgShowToast` وتوجيهه لـ `showToast`.
- تحويل صفحات: العملاء ← لوحات (عملاء · مشاريع · عقود · مستخلصات · ضمانات · …) بنفس تجربة الموظفين؛ المشاريع؛ الموردين؛ المخازن؛ الحسابات.
- الاختبار: لقطات شاشة قبل/بعد لكل صفحة + نفس اختبارات الوظائف الحالية (يجب ألا تتغير).

### المرحلة ب — مسار المشروع بنفس الشكل الأصلي
- نقل `ProjectPathTrack` الأصلي بحذافيره (الشريط الأفقي، الدوائر، تواريخ الخطوات، المرفقات، بالون «رجوع»، النسخة المصغّرة في جدول المشاريع، التفاعلية في النموذج) + CSS الـ `ppt-*`.
- المنطق الحالي (بوابات المراحل، التخطي بسبب، الرفض، سجل التغييرات، المحرر) يفضل تحت الواجهة كما هو، فنأخذ الشكل الأصلي + الضمانات اللي أضفتها.
- النتيجة: نفس الشكل في صفحة المشروع وجدول المشاريع وتفاصيل العميل.

### المرحلة ج — «مركز المتابعة» (صفحة واحدة = متابعة الموارد البشرية الموسّعة)
- **محرك تنبيهات واحد**: `registerAlertSource(name, fn)` ← كل مصدر يرجّع تنبيهات بنفس البنية (`level, icon, msg, issues, page, recordRef`).
- المصادر: موارد بشرية (الموجود كما هو) + موردين (فواتير متأخرة، إشعارات خصم) + مخازن (حد الطلب) + عملاء (خطوات متأخرة، ضمانات، مستخلصات غير مسددة، متابعات CRM، مشاريع بدون عقد، أوامر تغيير مسودة) + حسابات (تجاوز ميزانية، مستحقات).
- نفس شكل الكروت الحالي (`alert-card`) — بدون تغيير في المظهر، مع فلتر بالمصدر/الخطورة/المشروع.
- **لوحات** داخل نفس الصفحة بدل 3 لوحات منفصلة (الموردين/العملاء/الموارد). صفحة «مهامي» تتجمّع معاها.
- الملاحظات: نفس ستايل `notes-list` يتعمّم على كل الكيانات (عميل، مشروع، مورد، فاتورة، عقد…).

### المرحلة د — المصاريف والتكاليف الشاملة (دمج حقيقي)
- **محرك تكلفة واحد** `projectCostBreakdown(projectId)` يجمع: عمالة + معدات + وقود + صيانة + مصاريف + تكاليف + **فواتير موردين (صافي بعد المرتجعات)** + **صرف مخازن بالتكلفة** + سلف + مرتبات موزّعة.
- **قواعد منع العدّ المزدوج** (مكتوبة ومختبرة): فاتورة مورد مربوطة بحركة «وارد مخزن» تُحسب عند **الصرف** للمشروع لا عند الفاتورة؛ فاتورة مباشرة للمشروع تُحسب عند الفاتورة؛ دفعة المورد لا تُحسب تكلفة (هي تسوية).
- صفحتا «مصاريف شاملة» و«تكاليف شاملة» تتحولان لتبويبات حسب **المصدر** (عمالة/معدات/موردين/مخازن/مصاريف…) وحسب **المشروع**، وكشف حساب المشروع يستخدم نفس المحرك، فتنبيه الميزانية ولوحة الربحية يطلعوا بنفس الأرقام.

### المرحلة هـ — ربط المشاريع بالـ id وتنظيف
- ترحيل schema 9: إضافة `projectId` لكل سجل فيه اسم مشروع (عمال، معدات، مصاريف، تكاليف، فواتير موردين، حركات مخازن، حضور…) مع الإبقاء على الاسم للعرض والتوافق.
- لقطة احتياطية + تقرير بالسجلات اللي ملقتش مشروع مطابق (بدل ما تتخمّن).
- تحديث الاسم تلقائيًا في كل مكان عند تعديل اسم المشروع.

### المرحلة و — الإضافات المعتمدة (من البند 2)
تنفّذ بعد ما ينتهوا أ–هـ، حسب اختيارك.

## 4) الترتيب المقترح ومدة تقريبية للتنفيذ
1. ب (مسار المشروع) — الأسرع والواضح (طلبك المباشر).
2. أ (التصميم الموحد) ثم ج (مركز المتابعة).
3. د (التكاليف الشاملة) ثم هـ (ربط id).
كل مرحلة تتسلّم بنسخة zip + اختبارات + إمكانية الرجوع للنسخة السابقة، ومفيش مرحلة بتمس البيانات من غير لقطة احتياطية.

## 5) قرارات محتاجة منك
- هل «لوحات الأقسام» تشمل **كل** الصفحات (حتى المقايسات والعقود) ولا الأقسام الرئيسية فقط؟
- «متابعة الموارد البشرية» تفضل اسمها كده ولا نسميها «مركز المتابعة»؟
- الإضافات 1–7: أيهم تعتمد؟
- تكلفة مخزن/فاتورة: توافق على قاعدة «تُحسب عند الصرف للمشروع» لتفادي التكرار؟
