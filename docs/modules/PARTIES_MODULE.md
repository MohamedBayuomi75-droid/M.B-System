## 7. التشغيل الفعلي (الخطوات 6 و7 و11) — موافقة 2026-11-17

### البنية (migration `1764100000000-PartiesCutover`، مابتنقلش بيانات لوحدها)
- **`legacy_records` (view):** بيعرض records للمجموعات اللي ماتنقلتش، والجداول بالشكل القديم للمجموعات اللي اتنقلت. كل القراءة بتمر بيه:

  | المستخدم | القراءة |
  |---|---|
  | `/api/bootstrap` | ✅ |
  | `/api/changes` والبث اللحظي | ✅ |
  | التاريخ | ✅ |
  | المرفقات | ✅ |
  | الموديول | ✅ |

- **الكتابة من `/api/sync`** لمجموعة منقولة بتروح للجدول (`legacy_write_supplier/customer`) بنفس `rev`:
  - قواعد التعارض والتدقيق و`changes` زي ما هي.
  - رفض قيد في الجدول (مثلًا كود عميل مكرر أو بريد عميل غلط) بيرجع للواجهة **تعارض صريح** (`reason: 'constraint'`)، مش خطأ 500.
  - مفيش حاجة بتتحفظ نصها.
- **الحقول اللي مالهاش عمود** (المرفقات، والمصفوفات القديمة جوه العميل، وحقول `_lastEdit*`) بتتحفظ في `legacy_extra` زي ما هي.
- **سجلات records للمجموعة المنقولة بتتجمّد** (trigger)، فمفيش نسختين قابلتين للكتابة. حذفها نهائيًا بعد فترة الاستقرار بموافقة منفصلة.

### الأمر
```
# 1) على الخادم: نسخة كاملة + اختبار استعادة (OPERATIONS_SECURITY_BACKUP.md)
docker compose exec backup /opt/backup/backup-full.sh
docker compose exec backup /opt/backup/restore-test.sh
# 2) تجربة كاملة من غير أثر (بتنقل وتتحقق وبعدين ROLLBACK)
npm --prefix server run cutover -- parties dry-run
# 3) التنفيذ: بيرفض من غير نسخة كاملة ناجحة + اختبار استعادة ناجح بعدها، والمنفّذ لازم يأكّد وقت النسخة
npm --prefix server run cutover -- parties execute --by "<الاسم>" --backup-log <BACKUP_DIR>/backup-log.jsonl --confirm-backup <وقت النسخة>
# الرجوع (أي وقت): الجداول ← records بالحالة الحالية (شاملة اللي اتغيّر بعد النقل)
npm --prefix server run cutover -- parties rollback --by "<الاسم>" --backup-log ... --confirm-backup ...
```

**التنفيذ:**
- معاملة واحدة تحت قفل الكتابة العام: يا كله يا ولا حاجة.
- تحقق تكافؤ لكل سجل جوه المعاملة.
- تسجيل في سجل التدقيق (`module.cutover`).

### ملاحظات التشغيل
- **32 مورد رقمهم الضريبي «_»** (يعني مفيش رقم). الواجهة الحالية بتطبّق «≥ 5» عند الإضافة بس، فالقيد اتشال من الجدول:
  - بيتنقلوا زي ما هم.
  - الـ API بيتحقق من الرقم الضريبي عند الإضافة أو التغيير بس، زي الواجهة الحالية بالظبط.
  - تحويل «_» لفاضي = معالجة بموافقة منفصلة.
  - القائمة للمراجعة برا المستودع.
- **بريد المورد:** نفس الوضع. الواجهة بتتحقق منه عند الإضافة بس، فقاعدته في الـ API بنفس السلوك، مش قيد جدول.
