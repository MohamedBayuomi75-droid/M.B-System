## 2. اللي الاستكشاف طلّعه (مثبّت في `phase89.js`)
1. **F-10:** مصروف بسطور (شاي 40 + مياه 60) تكلفته **صفر** على المشروع — `projectCostSummary` بيقرا `amount` بس.
2. **F-11:** فاتورة مورد (أساس 1000 + ضريبة 140 − مخصوم 10 = صافي 1130) بتدخل بـ **1140** (الإجمالي قبل الخصم).
3. فاتورة مربوطة بإضافة مخزن مابتدخلش وقت الفاتورة، وبتدخل وقت الصرف؛ والصرف من غير تكلفة مثبّتة بيتحسب بمتوسط التكلفة **الحالي**.
4. **«السلف» = صفر دايمًا.**
5. الربط بالاسم: تكلفة على «مشروع قديم» (مش مسجّل) بتظهر في الشاملة بعلامة «اسم غير مسجّل كمشروع».
6. حالة الميزانية بتتحسب على التكلفة **الكلية** مش على الفترة (المشروع اللي تكلفته في الفترة صفر بيبان «ضمن الميزانية»).
7. **في نافذة التكلفة:** عنوان خانة «نوع التكلفة (القسم)» بيتكتب عليه «بنود التكلفة» (نفس غلطة تخطيط النوافذ في المستحقات).
8. فتح صفحة التكاليف بيعمل قايمة أقسام فاضية لكل فئة اتفتحت (`costSections.supervisors = []`).

## 5. الـ API (8.8.3)
| المسار | المحتوى |
|---|---|
| `GET /api/v1/project-cost` | الشاملة بالحسابين: الأعمدة التسعة، والمحصّل، والمحصّل − التكلفة، والإجمالي، **والأسماء الغير مسجّلة** (د-4)، وعدد اليوميات المستنية مراجعة |
| `GET /api/v1/project-cost/one?name=` | مشروع واحد بالحسابين، وبنود الموردين والمخازن بالحسابين |
| `GET /api/v1/project-cost/by-project` | التكلفة وحالة الميزانية لكل مشروع مسجّل (عمود صفحة المشاريع) |
| `GET /api/v1/costs/boards` و`table` و`form-options` و`:id` | لوحات الفئات، ولوحات الأقسام والجدول بنفس الفلاتر، وخيارات النافذة (الأشخاص، والأقسام، والبنود المقترحة) |
| `POST /api/v1/costs` و`PATCH :id` و`DELETE :id` | الحفظ بالسطور بنفس زرار الحفظ القديم (Idempotency-Key، وrev، وحدث `cost.saved` / `cost.deleted`) |
| `POST /api/v1/costs/sections` و`items` | الأقسام (إضافة، وتغيير اسم بيغيّر التكاليف، وحذف) والبنود (إضافة، وتغيير اسم بيغيّر التكاليف، وحذف من القايمة) |

**الصلاحيات:** صفحة التكاليف بصلاحيات `costs`؛ وتكلفة المشروع لأي حد ليه عرض «المشاريع» أو «التكاليف» أو «المصاريف» (زي القديمة).
**الاختبار:** `costs.e2e` (الحسابين قبل النقل وبعده، والحفظ، والأقسام، والبنود، والتعارض، والأحداث، والصلاحيات).
