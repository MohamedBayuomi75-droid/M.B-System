## F-01 فاتورة مشتريات من مورد (Supplier Purchase Invoice)
| البند | المحتوى |
|---|---|
| **المقترح** | `سطر = round4(كمية × سعر الوحدة)` · `الإجمالي = Σ السطور` · `الخصم التجاري = round4(الإجمالي × نسبة الخصم)` أو مبلغ · `الصافي = الإجمالي − الخصم` · `القيمة المضافة = round4(الصافي × نسبة كود VAT)` · `الدمغة = حسب كود STAMP` (لو المورد بيحمّلها) · `إجمالي الفاتورة = الصافي + القيمة المضافة + الدمغة` · `الخصم تحت الحساب = round4(الصافي × نسبة كود WHT)` لو الصافي > الحد الأدنى · `المستحق للمورد = إجمالي الفاتورة − الخصم تحت الحساب` |
| **الحالي** | `الإجمالي = baseValue + vat + stampDuty` و`الصافي = الإجمالي − withheld`، **كلهم مبالغ يدوية**، و`roundMoney(…,6)` (`ledger/helpers.js:132,150`). الحسابات التانية بتستخدم المخزّن |
| **الفرق** | المقترح بيحسب من السطور والأكواد بدل الإدخال اليدوي، و4 خانات بدل 6. ولقيت 52 فاتورة نسبها مختلفة (`TAX_ENGINE.md §8.3`) |
| **المتغيرات** | الكمية (5 خانات)، وسعر الوحدة (5 خانات)، ونسبة الخصم، وأكواد VAT/STAMP/WHT (B-21)، والحد الأدنى للخصم |
| **مثال** | سطرين: 10 × 125.5 = **1255.0000** · 3.5 × 40.12345 = 140.431575 ← **140.4321** · الإجمالي **1395.4321** · خصم 2% = **27.9086** · الصافي **1367.5235** · ق.م 14% = **191.4533** · الإجمالي **1558.9768** · خصم تحت الحساب 1% = **13.6752** · المستحق **1545.3016** |
| **القيد** | من حـ/ المشتريات أو المخزون أو تكلفة المشروع 1367.5235 · من حـ/ ضريبة القيمة المضافة — مدخلات 191.4533 · إلى حـ/ المورد 1558.9768. **وعند الخصم تحت الحساب:** من حـ/ المورد 13.6752 إلى حـ/ مصلحة الضرائب — خصم وإضافة 13.6752 |
| **الاستثناءات** | المرتجع: مستند مستقل مربوط بالأصل، بالسالب (TR-03) · الإلغاء = أثر صفر (TR-02) · ق.م غير قابلة للخصم بتتضاف للتكلفة · المورد غير المسجّل (مفيش ق.م) |
| **المرجع** | معيار المحاسبة المصري 2 (المخزون: الضرائب غير القابلة للاسترداد جزء من التكلفة) · ق 67/2016 (ق.م) · ق 91/2005 م 59 (الخصم تحت الحساب) — **للاسترشاد، يؤكده المدير المالي** |
| **قرار المدير المالي** | (1) التقريب سطر ولا مستند؟ (2) الخصم تحت الحساب بيتسجّل عند الفاتورة ولا عند الدفع؟ (3) قابلية خصم ق.م لكل فئة مشتريات (4) الدمغة على مين؟ |

|---|---|

| **المرجع** | معيار المحاسبة المصري 48 (الإيراد من العقود مع العملاء) · ق 67/2016 |
| **قرار المدير المالي** | هل فيه فواتير مبيعات غير المستخلصات أصلًا؟ ولو آه، أنهي أنواع؟ |

## F-03 مستخلص عميل (Customer Progress Certificate) — TR-11 معتمد
| البند | المحتوى |
|---|---|
| **المقترح** | `الإجمالي التراكمي = الأعمال السابقة + الحالية + الإضافات − المستبعد` · `المحتجز = round4(التراكمي × نسبة بند العقد)` (قرار الاحتجاز: من العقد) · `استرداد الدفعة المقدمة التراكمي` (بند العقد) · `استقطاعات تعاقدية` (أكواد CONTRACTUAL) · `الصافي التراكمي = التراكمي − المحتجز − الاسترداد − الاستقطاعات` · `مستحق الفترة = الصافي التراكمي − صافي المستخلصات السابقة` · `ق.م = round4(إجمالي الفترة × كود VAT حسب تاريخ العقد)` (VAT-CONSTR-NEW أو TRANS — B-21) |
| **الحالي** | `إجمالي = value + extras − excluded` (**من غير الأعمال السابقة**)، و`صافي = إجمالي − deductions − advanceDeduct − إجمالي×retentionPct% − إجمالي×taxPct%` بخانتين (`clients/pages-invoices.js:6`). **الضريبة بتتطرح كاستقطاع**، والاحتجاز افتراضيه 5% في الكود |
| **الفرق** | **(1)** تراكمي بدل فترة. **(2)** الضريبة: الحالي بيطرحها كاستقطاع، وده ممكن يكون المقصود بيه **الخصم تحت الحساب** اللي العميل بيخصمه، مش ق.م. والمقترح بيفصلهم: ق.م بتتضاف، والخصم تحت الحساب منفصل. **(3)** الاحتجاز من العقد |
| **مثال** | سابق 100,000 + حالي 50,000 + إضافات 5,000 − مستبعد 2,000 = تراكمي **153,000** · محتجز 5% = **7,650** · استرداد مقدم 10,000 · استقطاعات 500 · الصافي التراكمي **134,850** · سابق مدفوع 90,000 ← مستحق الفترة **44,850** · إجمالي الفترة 53,000 × ق.م 14% = **7,420** ← بالضريبة **52,270**. **الحالي لنفس البيانات: 39,850** |
| **القيد** | من حـ/ العميل (مستحق الفترة + ق.م) ومن حـ/ محتجزات لدى العملاء (محتجز الفترة) إلى حـ/ الإيرادات (إجمالي الفترة) وإلى حـ/ ق.م مخرجات. **واسترداد الدفعة المقدمة:** من حـ/ دفعات مقدمة من العملاء إلى حـ/ العميل |
| **الاستثناءات** | المستخلص الختامي · رد المحتجز عند الاستلام (B-41 مفتوح) · الغرامات (بند عقد) · المعاملة الانتقالية للعقود القديمة (قرار 418/2025 — للمستشار) |
| **المرجع** | معيار المحاسبة المصري 48 (الاعتراف بالإيراد على مدار الوقت بطريقة المخرجات) · B-21 · قرار الاحتجاز (2026-11-17) |
| **قرار المدير المالي** | (1) `taxPct` الحالي معناه ق.م ولا خصم تحت الحساب؟ (2) أساس ق.م: إجمالي الفترة ولا الصافي بعد المحتجز؟ (3) الاعتراف بالإيراد بالمستخلص المعتمد؟ |

## F-04 مستخلص مقاول باطن (Subcontractor Progress Certificate)
| البند | المحتوى |
|---|---|
| **المقترح** | نفس هيكل F-03 من ناحية الدفع: تراكمي ← محتجز (بند العقد) ← استرداد مقدم ← استقطاعات وغرامات ← صافي تراكمي ← مستحق الفترة. وفوقهم: `الخصم تحت الحساب = round4(صافي الفترة × WHT-CONTR)`، وق.م مدخلات لو مقاول الباطن مسجّل |
| **الحالي** | **مش موجود** (مقاولي الباطن بيتسجّلوا كموردين أو مصروفات) |

| **القيد** | من حـ/ تكلفة المشروع (إجمالي الفترة) ومن حـ/ ق.م مدخلات إلى حـ/ مقاول الباطن وإلى حـ/ محتجزات مقاولي الباطن (التزام) وإلى حـ/ ضرائب خصم وإضافة |
| **الاستثناءات** | رد المحتجز بعد الاستلام · الغرامات |
| **المرجع** | معيار المحاسبة المصري 48 (من ناحية التكلفة) · ق 91/2005 م 59 |
| **قرار المدير المالي** | هل نحتاج مستند مستخلص باطن منفصل؟ ولا يفضل فاتورة مورد بنوع «مقاول»؟ |

| **القيد** | الرصيد ناتج مش قيد. وبعد المحاسبة = رصيد حساب المورد المساعد |
| **الاستثناءات** | 165 دفعة من غير اتجاه بتفضل غير مصنّفة لحد المراجعة الفردية (B-53) |
| **المرجع** | TR-02…TR-06 |
| **قرار المدير المالي** | ✅ معتمد كقاعدة. المطلوب: اعتماد الأرصدة الافتتاحية للنظام الجديد |

## F-08 مستحقات العمالة اليومية (Daily Worker Dues) — TR-07/08 معتمدة
| البند | المحتوى |
|---|---|
| **المقترح** | `يومية = round4(الأجر المسجّل يوم الحضور × معامل الحالة) − الخصم`، بحد أدنى صفر. المعاملات (B-76): حاضر 1، ونصف ½، ومتأخر 1 − الخصم، وغائب أو عطلة 0. **أي حالة تانية بتتعزل** · المكرر واليتيم بيتعزلوا (TR-08) · `مستحق الفترة = Σ` · `المتبقي = المستحق + الإضافات المعتمدة − المدفوع − الجزاءات − المصاريف` |

| **الاستثناءات** | الإجازات (B-73)، والصرف فوق المستحق (B-47) |
| **المرجع** | TR-07، TR-08، B-76 |
| **قرار المدير المالي** | ✅ القاعدة معتمدة. B-47 مفتوح |

## F-09 تكلفة الاستلام المخزني (Inventory Receipt Costing) — B-49 / TR-13 معتمدة
| البند | المحتوى |
|---|---|
| **المقترح** | `تكلفة وحدة الاستلام = (صافي سطر الفاتورة بعد الخصم + الضرائب غير القابلة للخصم + تكاليف مباشرة معتمدة) ÷ الكمية` (5 خانات) · `المتوسط الجديد = round5((كمية قبل × متوسط قبل + كمية الاستلام × تكلفة وحدته) ÷ (كمية قبل + كمية الاستلام))`، ولو الكمية قبل ≤ 0 فالمتوسط = تكلفة الاستلام · **المتوسط على مستوى الصنف ولا الصنف × المخزن: قرار** |
| **الحالي** | نفس الفكرة بخانتين، والكمية من **كل المخازن**، والحساب في الواجهة (`warehouses/helpers.js:66`) |
| **الفرق** | الدقة (5 خانات)، ومكوّنات التكلفة، والخادم بدل الواجهة |
| **مثال** | قبل: 7 بمتوسط 12.34567 · استلام 3 بـ 15.1 ← (86.41969 + 45.3) ÷ 10 = 13.171969 ← **13.17197** (الحالي **13.17**) |
| **القيد** | من حـ/ المخزون (القيمة) إلى حـ/ المورد أو مخزون بالطريق |
| **الاستثناءات** | المرتجع للمورد بتكلفة الاستلام الأصلية · التسوية بالزيادة (B-51): التكلفة؟ |
| **المرجع** | معيار المحاسبة المصري 2 (المتوسط المرجّح) |
| **قرار المدير المالي** | (1) المتوسط لكل صنف ولا لكل صنف × مخزن؟ (2) مكوّنات تكلفة الاستلام (نقل وتحميل)؟ (3) تكلفة تسويات الزيادة (آخر تكلفة؟ المتوسط؟ يدوي معتمد؟) |

## F-10 تكلفة الصرف المخزني (Inventory Issue Costing) — TR-13 معتمدة
| البند | المحتوى |
|---|---|
| **المقترح** | `تكلفة وحدة الصرف = المتوسط الساري وقت الصرف` (بتتثبّت على الحركة ومابتتعادش) · `قيمة الصرف = round4(الكمية × تكلفة الوحدة)` · B-50 (مفيش صرف فوق المتاح) |
| **الحالي** | `unitCost = avgCost` الحالي (خانتين) وقت الصرف. وتكلفة المشروع بتاخد المسجّل، ولو مش موجود المتوسط **الحالي** (F-17) |
| **الفرق** | الدقة، والتثبيت إلزامي |
| **مثال** | صرف 4 × 13.17197 = **52.6879** (الحالي 4 × 13.17 = **52.68**) |
| **القيد** | من حـ/ تكلفة المشروع (أو المصروف) إلى حـ/ المخزون |
| **الاستثناءات** | تسوية العجز والتلف (B-51) بنفس تكلفة الصرف ← حساب خسائر مخزون؟ |
| **المرجع** | معيار المحاسبة المصري 2 |
| **قرار المدير المالي** | حساب العجز والتلف: تكلفة مشروع ولا خسائر؟ |

## F-11 تكلفة تشغيل المعدات (Equipment Operating Cost)
| البند | المحتوى |
|---|---|
| **المقترح** | `تكلفة اليوم = (ساعات × سعر الساعة) أو (أيام × سعر اليوم)` من **جدول أسعار معتمد بإصدار** · `+ الوقود = لتر × سعر اللتر` · `+ الصيانة المحمّلة` · وللمعدات المملوكة: إهلاك (B-43) |
| **الحالي** | `cost` المسجّل، ولو مش موجود: سلسلة بدائل (أيام × سعر، ساعات × سعر، أيام × 8 × سعر الساعة…) + الوقود، وكل جزء بخانتين (`core/helpers.js:7778`) |
| **الفرق** | جدول أسعار معتمد بدل البدائل الضمنية (زي «8 ساعات») |
| **مثال** | 2 يوم × 1000 + 10 لتر × 12.5 = **2125.0000** (الحالي 2125) |
| **القيد** | من حـ/ تكلفة المشروع (معدات) إلى حـ/ المورد (إيجار) أو مخصص الإهلاك أو مخزون الوقود |
| **الاستثناءات** | المعدة المملوكة مقابل المستأجرة |
| **المرجع** | معيار المحاسبة المصري 10 (الأصول الثابتة) |
| **قرار المدير المالي** | **B-42 (تحميل التكلفة) وB-43 (الأصول): مانعين** · «8 ساعات = يوم»: معتمد؟ |

## F-12 التكلفة الفعلية للمشروع (Project Actual Cost) — TR-10 معتمدة
| البند | المحتوى |
|---|---|
| **المقترح** | `= Σ العمالة (F-08 المعتمدة) + Σ المعدات (F-11) + Σ سطور فواتير الموردين المحمّلة على المشروع بالصافي بعد الخصم (من غير المشتريات اللي دخلت المخزن) + Σ الصرف المخزني بتكلفته المثبّتة (F-10) + Σ مستخلصات الباطن (F-04) + Σ المصروفات (كل السطور)` · المرتجع بالسالب، والملغى صفر · ق.م: تكلفة بس لو غير قابلة للخصم · الربط **بمعرّف المشروع** (B-34) · غير المباشرة (B-33) |
| **الحالي** | `totalInvoice` (شامل الضريبة وقبل الخصم)، والمصروفات `amount` بس (المصروف بسطور = صفر)، والربط بالاسم (`core/helpers.js:7816`) |
| **الفرق** | الصافي، والسطور، والمعرّف، وتكلفة الصرف المثبّتة |
| **مثال** | عمالة 40,000 + معدات 12,500 + موردين صافي 55,930.25 + صرف مخزني 8,000 + مصروفات 2,000 = **118,430.25** |
| **القيد** | مجموع أرصدة حسابات تكلفة المشروع (بُعد المشروع / مركز التكلفة) |
| **الاستثناءات** | التكاليف غير المباشرة (B-33) |
| **المرجع** | TR-10 · معيار المحاسبة المصري 48 (تكاليف العقد) |
| **قرار المدير المالي** | ✅ القاعدة معتمدة. B-32/B-33 مفتوحين |

## F-13 ربحية المشروع (Project Profitability)
| البند | المحتوى |
|---|---|

## 16. محرك القواعد المالية — التصميم المقترح (بيتبني بعد الاعتماد)
**الإصدارات:**
- **مكوّنات كل معادلة:** كود فريد، واسم، وموديول، وإصدار.
- **التعبير:** محدود (انظر الأمان تحت).
- **المتغيرات:** متعرّفة بالنوع (مبلغ 4، كمية 5، نسبة، تاريخ، قائمة)، والمعاملات (نسب وثوابت بإصدارات أو مربوطة بأكواد B-21)، وشروط التطبيق، وتاريخ السريان من/إلى.
- **الحالة:** مسودة ← بانتظار الاعتماد ← معتمد ← موقوف، **والاعتماد من شخص غير المنشئ** (زي B-21).
- **حالات اختبار إلزامية:** مدخلات ← نتيجة متوقعة. **لازم تنجح قبل الإرسال للاعتماد.**

**التطبيق:**
- الخادم بيختار الإصدار المعتمد الساري بتاريخ المستند.
- المستند المرحّل بيحتفظ بـ (كود المعادلة، والإصدار، والمدخلات، والنتيجة)، **ومفيش إعادة احتساب تلقائية**.

**الأمان (البند 5):**
- **مفيش JavaScript ولا SQL ولا `eval`.**
- محلّل (parser) خاص بقواعد ثابتة بيحوّل التعبير لشجرة.
- **المسموح بس:**
  - أرقام عشرية نصية والمتغيرات المعرّفة.
  - العمليات `+ − × ÷` والمقارنات و`و/أو/مش`.
  - الدوال: `round(x, n)` (HALF_UP بس)، و`min`، و`max`، و`abs`، و`if(شرط، أ، ب)`، و`sum(سطور، تعبير)`، و`tax(كود)` (أكواد B-21 المعتمدة)، و`rate(اسم)` (معامل بإصدار).
- **الحسابات:** بـ decimal (مش float).
- **حدود:** طول التعبير وعمقه وعدد العمليات.
- **القسمة على صفر** = خطأ صريح.

**الشاشة «Financial Rules Management»:**
- **الحقول:** الاسم، والكود، والموديول، والإصدار، والصيغة، والمتغيرات، والشروط، والسريان، وحالة الاعتماد، وسجل التعديلات.
- **وفيها:** تشغيل حالات الاختبار، ومعاينة النتيجة بمدخلات يدوية.
