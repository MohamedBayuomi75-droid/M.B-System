## 4. التصميم (البند 6) — migration `1764200000000-TaxEngine`
| الجدول | الدور |
|---|---|
| `tax_codes` | الكود الفريد، والاسم، والنوع (`VAT/SCHEDULE/WHT/STAMP/PAYROLL_TAX/SOCIAL_INSURANCE/CONTRACTUAL`)، و`is_tax` (= مش تعاقدي، بقيد)، والحالة (نشط/موقوف) |
| `tax_code_versions` | الإصدار بكل حقول القرار. انظر التفاصيل تحت الجدول |
| `document_tax_lines` | **لقطة لكل مستند**: الإصدار المستخدم، والأساس، والجزء الخاضع، والنسبة، والمبلغ، وسبب الإعفاء. مابتتعادش لو النسبة اتغيّرت |

**حقول `tax_code_versions`:**

| المجموعة | الحقول |
|---|---|
| الحساب | الطريقة (`PERCENT`/`FIXED`/`BRACKETS`)، والنسبة (6 خانات)، والقيمة الثابتة، والشرائح، والأساس، و`base_ratio` (الجزء الخاضع من الأساس)، والحد الأدنى للأساس |
| الانطباق | المستندات اللي بينطبق عليها، والطرف المتحمّل، وطريقة التحصيل أو التوريد |
| الشروط والإعفاءات | الشروط (تاريخ العقد من/إلى، والأنشطة، وأنواع الأطراف)، والإعفاءات (بسبب)، و`allow_stacking` |
| السريان والمراجع | تاريخ السريان من/إلى، والمرجع القانوني، وملاحظات المدير المالي، وملاحظات المستشار |
| التتبع | سبب التعديل، ومين أعدّ وأرسل واعتمد وإمتى |

**القيود في قاعدة البيانات:**
- **الاعتماد:** مفيش اعتماد من غير مرجع قانوني ومعتمد. **والمعتمد ≠ اللي أعدّ (B-04)**.
- **الإصدار المعتمد مابيتعدّلش** (trigger). الاستثناءين الوحيدين:
  - إيقافه.
  - قفل سريانه المفتوح مرة واحدة لما إصدار أحدث بنفس الشروط يتعتمد.
- **الحذف:** مفيش حذف لإصدار اتبعت للاعتماد. المسودة بس اللي تتمسح.
- **الأرقام:** قيم الطريقة متسقة (CHECK)، والنسبة بين 0 و100.

**الحساب** (`server/src/finance-rules/tax-calc.ts`، دالة صافية):
- **على الخادم بس، وبالإصدار المعتمد الساري بس.**
- **مفيش إصدار مطابق** ← `NO_APPROVED_RATE`. مفيش نسبة افتراضية ولا رجوع لمسودة.
- **أكتر من إصدار مطابق** ← `AMBIGUOUS_RATE`.
- **التكرار** ← `DOUBLE_APPLICATION`: ضريبتين من نفس النوع على نفس الأساس، أو نفس الكود مرتين. الاستثناء لو الإصدارين بيسمحوا بـ `allow_stacking` بسند قانوني.
- **التقريب:** 4 خانات HALF_UP: الجزء الخاضع بيتقرّب، وبعدين الضريبة.
- **الشرائح تصاعدية:** كل شريحة بنسبتها على الجزء اللي جواها بس.
- **الإعفاء والحد الأدنى** ← المبلغ صفر، والسبب بيتسجّل في السطر.

**الصلاحيات** (من غير أدوار جديدة):
- الإعداد (كود، مسودة، إرسال، مسح مسودة) لمدير النظام بس، فالمستخدمين العاديين مايغيّروش النسب.
- الاعتماد والرفض والإيقاف لصاحب فعل «اعتماد» (`docActions.approve`، بيتمنح لكل مستخدم) **وبشرط إنه شخص غير اللي أعدّ**.
- **المدير المالي والمستشار الضريبي** بياخدوا الصلاحية دي بمنح المدير لما حساباتهم تتعمل.

**التدقيق:** كل عملية بتتسجّل في سجل التدقيق (`tax.code.create`، و`tax.version.create/submit/approve/reject/suspend/delete_draft`) ومعاها القيم والسبب.

**الربط بمحرك القواعد المالية (B-20)** — موديول `finance-rules`:
- **الضرائب هي أول عائلة**، بنفس المبادئ: إصدارات، وسريان بتاريخ، وإعداد واعتماد منفصلين، ولقطة لكل مستند، ومفيش إعادة احتساب تلقائية.
- **عائلات المعادلات التانية** (صافي الفاتورة، والمستخلص، ورصيد المورد، ومستحقات العمالة) بتتضاف لنفس الموديول **بعد** مراجعة المدير المالي واعتماده (B-20 §6).
- **الموديولات** (الفواتير 6.3، والمستخلصات 6.5، والمرتبات) بتستدعي `TaxesService.computeAndSnapshot()` جوه معاملة المستند.

## 5. الشاشة والـ API (البند 7)
- **الشاشة:** `/app/taxes`، «الضرائب والاستقطاعات». ظاهرة للمدير ولصاحب فعل «اعتماد» بس، وفيها:
  - إضافة كود.
  - إصدار جديد كمسودة بكل الحقول.
  - إرسال ومسح مسودة.
  - اعتماد ورفض وإيقاف بملاحظة (والزرار مش ظاهر لللي أعدّ).
  - معاينة حساب بالمعتمد الساري بس.
- **الـ API:**

| الطلب | الوظيفة |
|---|---|
| `GET /api/v1/finance/taxes` | الأكواد والإصدارات |
